# Input and reading boundary

Supply `manuscript.md` in Pandoc Markdown and `book.json` with `schema_version: 1`, nonempty `title`, `language` (language tag) and `identifier` strings. Additional descriptive settings are ignored. The manuscript supports headings, prose, emphasis, strong text, inline code, code blocks, lists, block quotes, Unicode and footnotes, including repeated references. Use at least one footnote. Undefined, duplicate and unused note definitions are errors. Raw HTML, authored hyperlinks, images, mathematics, tables, citations and nested notes are rejected. Local assets and covers are outside this text-book boundary.

The EPUB has a contents document, a continuous reflowable reading spine and an endnote spine item. Identical note bodies share one note; every referring marker receives a unique ID and its own labelled backlink. This is navigation, not a popup implementation. Reader software may present these semantics differently.

Text comparison collapses whitespace runs to a single space and excludes generated marker numbers, note headings and return labels. All remaining punctuation, case and Unicode must match the parsed source. Markdown syntax is interpreted by Pandoc; it is not literal book text. The fixed modified timestamp is required EPUB package metadata, not a claimed publication date. No author, producer, machine path or revision metadata is embedded.

The custom browser reader loads the EPUB’s extracted XHTML in an iframe. Its controls open the shipped navigation document and adjust the root font size. Anchor clicks and returns use Chromium’s ordinary navigation. The offline test extracts only the archive just produced and checked; it does not create another rendering of the manuscript. No external font or network service is used. The EPUB requests a serif fallback; the recorded container uses DejaVu Serif. No fonts are embedded in the EPUB. Page proof restricts Fontconfig to the DejaVu directory with `source/fonts.conf`, so platform-specific font requests also fall back to these permissively licensed fonts.

`run.sh --check` inspects existing output, checks recorded hashes and re-exercises browser links. The reader screenshots and source map remain in output. To inspect interactively, unzip the EPUB into a local folder, place `source/reader.html` there, serve that folder on localhost and open the reader. Browser security settings may prevent iframe access when opened directly from the filesystem; the automated reader uses a bounded local-file-access flag inside its offline container.

The case Dockerfile mirrors the shared recipe. `run.sh` uses the shared runner and supplies pinned optional packages; the shared runner builds that recipe as `dp-kindle:1`. Only Git and Docker are host prerequisites. Work runs offline with read-only input and source mounts, a separate writable output mount, a fresh temporary profile and bounded resources. A normal run writes only into its selected output directory. The case-page screenshot step depicts the tracked case page; replacement manuscripts generate their own reader proof in output.
